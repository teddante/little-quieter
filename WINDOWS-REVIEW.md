# Windows implementation review

Reviewed against published guidance available on 25 October 2026. This is an implementation review, not a certification of all Windows standards or future 2027 requirements.

| Area | Implementation |
|---|---|
| Supported runtime | .NET 10 LTS Windows Forms, using the installed shared Windows Desktop runtime so installed servicing updates apply. [Microsoft support policy](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core). |
| Windows audio | Shared, event-driven WASAPI through pinned NAudio.Wasapi 3.3.0. Both streams request the minimum shared engine period through IAudioClient3, with a 10 ms standard-mode fallback. Native mix formats avoid resampling. MMCSS uses the Audio task. Other apps retain device access. [Capture guidance](https://github.com/naudio/NAudio/blob/v3.3.0/Docs/WasapiRecorder.md), [playback guidance](https://github.com/naudio/NAudio/blob/v3.3.0/Docs/WasapiPlayer.md). |
| Small distribution | One framework-dependent executable; no bundled .NET runtime, web browser engine or unused Windows Runtime SDK projection. Only the WASAPI package and its core dependencies are included. |
| Startup and permissions | Current-user installation and startup, quoted executable path, visible startup toggle, ordinary user privileges and a tray menu with Stop/Exit. No service, administrator access or microphone privacy changes. [Run key guidance](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys). |
| Display scaling | PerMonitorV2 through the .NET project configuration, with scrolling on smaller displays. [WinForms scaling guidance](https://learn.microsoft.com/en-us/dotnet/desktop/winforms/forms/autoscale). |
| Accessibility | Standard keyboard-operable Windows controls, explicit control names, updated Start/Stop/Learn accessible names, system colors when launched in high contrast, and a text reminder alongside sound. No warning is conveyed only by color. |
| Interruption and sound | Reminder window requests no activation. The continuous 2.5 kHz source has no loop boundary. A prepared output stream emits silence between alarms; its atomic gate applies the loud/quiet decision without a new device initialization or playback thread. Approximately 0.5 ms gain ramps avoid switching clicks. Volume and mute remain under user control. Two narrow notches reduce acoustic alarm echo. |
| Responsiveness and overhead | Native microphone callbacks produce 5 ms RMS readings and update the output gate directly. UI summaries are limited to 20 per second; hidden quiet windows refresh at 250 ms, and visible/active windows at 100 ms. Repeated unchanged decisions avoid redundant output writes. A separate 20 ms watchdog closes stale capture after 100 ms without data. Device notifications silence the gate and request reconnection. |
| App-only routing | An explicit output selection lets the alarm bypass a virtual enhancement endpoint while other apps retain their routes. Only Little Quieter preferences store that selection. A missing selected output fails visibly rather than moving the alarm to an unexpected speaker. |
| Simplification | Removed speech synthesis, custom reminder text, configurable delay, cooldown data and the delayed-onset accumulator. Calibration, volume, startup and a fixed visual warning remain. Obsolete settings are pruned at startup. |
| Data and maintenance | Audio stays in memory; no recording, transcription, account, telemetry or network code. Preferences use validated values and atomic replacement. SDK projects, dependency lock file, deterministic compilation, analyzers and warnings-as-errors are included. |

Version 1.3.1 validation includes a Release publish, 39 focused checks, zero-volume native capture/playback checks and installed-session verification on a development PC. Muted endpoint-clock tests measured output start/stop over 24 cycles per run. Routing only the alarm directly to a physical endpoint cut median timing to about 8.8/9.4 ms, compared with about 57/58 ms at the FxSound virtual endpoint on that machine. The latter is not a measurement of FxSound's final physical output. See [timing and resource report](LATENCY-AND-PERFORMANCE.md) for method and limits. No audible alarm or computer-use action was used during verification.

Actual audible start/stop latency, speaker/room feedback, device-switch reconnection, the compacted interface, multi-monitor transitions, screen-reader behavior, dynamic high-contrast changes and a full reboot have not been exercised interactively. Hardware, Bluetooth, audio enhancements and driver buffers can add latency beyond the software stages. Distortion or clipping can defeat narrow-band echo rejection; headphones avoid acoustic feedback. The app applies contrast colors at launch. The build is unsigned. Windows certification and compatibility with unpublished future requirements are not claimed.

The version 1.3.2 source refactor separates audio, controls and settings by responsibility, shares preview lifetime with the gate, reports unexpected output stops, and keeps calibration startup suspended. Steady synthetic analysis/gating/tone generation is checked for zero managed allocations. The meter reuses three brushes per paint. Build, checks, packaging and CI share the same scripts and project settings. These changes do not establish new acoustic-latency or gaming-performance results; the measurements linked above remain labelled version 1.3.1.
